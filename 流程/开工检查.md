# 开工检查

> 每次卓望任务开工无条件先跑。不跑完不得开始分析、策划、写文案、做原型或生成交付文件。

## 步骤

### 1. 同步知识库

```
git -C <本地克隆路径> status --short
git -C <本地克隆路径> pull --ff-only
```

- 有未提交改动、冲突、或 `pull` 失败（含 DNS/网络失败）→ **停下报告，不得强行覆盖**
- 网络失败时必须明说「远端状态未验证，当前用的是本地副本」，不得声称已同步
- 只有 `Already up to date.` 或成功快进才算验证通过

ChatGPT 网页版走 GitHub Connector 直读远端，跳过本步。

### 2. 完整读取三件套

按顺序读完，不得用旧摘要代替：

1. `AGENTS.md` —— 知识库自身维护规则
2. `卓望.md` —— 全部业务知识与规范
3. `进度.md` —— 确认本次相关项目的**当前版本／状态／下一步／最近经手**

从 `进度.md` 确认这个项目别人做到哪了，避免重复劳动或基于过时版本推进。

### 3. 确认原型精度（涉及原型时）

`卓望.md` →「交付偏好」已明确：**精度由用户在下达任务时决定，不设默认强制值。**

- 用户说了低保真／高保真 → 照做
- 用户没说 → **主动问**，不得自行假定
- 不得把某个历史项目的精度约束跨项目套用

### 4. 确认设计软件在线（涉及 Figma / Open Design 时）

- Figma 桌面端是否打开？插件桥是否运行？
- Open Design 是否打开？
- 用户刚重启机器或重开工具时，主动提醒先打开这两个桌面软件再继续
- 连接配置是持久的，只需重新「打开软件」，不需要重新配置

### 5. 明确本次待确认项

对方言、民俗、赛事、政策、活动时间、名单、奖品、数值、库存、概率、兑换门槛、发放方式——
**必须查证**；无法确认的一律标「待确认」，不得当作稳定事实写入档案或交付物。

## 验收清单

- [ ] 仓库已同步，或已明确报告远端状态未验证
- [ ] `AGENTS.md`、`卓望.md`、`进度.md` 三份都完整读过
- [ ] 已从 `进度.md` 确认相关项目当前状态
- [ ] 涉及原型时，精度已由用户明确
- [ ] 涉及 Figma／Open Design 时，软件可用性已确认
- [ ] 待确认项已列出
