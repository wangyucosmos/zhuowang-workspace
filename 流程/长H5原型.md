# 长 H5 原型

> 输出：移动端纵向长 H5 活动页原型。
> 前置：先跑 [开工检查.md](开工检查.md)，**其中第 3 步「确认原型精度」不可跳过**。

## 步骤

### 0. 有参考页时，先扒它的线上配置（不要只看截图猜结构）

用户给出咪咕活动页链接（`m.miguvideo.com/m/provincevml/<pageId>`）时，页面 HTML 里已内嵌完整组件树、
tab 结构、弹窗清单和活动规则全文，直接抓下来即可：

```
curl -s -m 25 -A "<移动端 UA>" "https://m.miguvideo.com/m/provincevml/<pageId>?needLazyimg=0" -o page.html
```

再用正则把中文串按出现顺序去重打印，就能还原模块顺序（组件名形如 `9月-累计打卡-<hash>`）、
每个模块的按钮与弹窗、以及规则里的奖品名、门槛、次数上限、方案编号和排除人群。

- **WebFetch 一类的取正文工具只会拿到空壳 SPA（只有「咪咕视频」四个字），必须用 curl 取原始 HTML。**
  2026-09-09 实测：同一链接 WebFetch 返回空壳，curl 返回约 350KB 完整配置。
- 扒到的模块骨架与结构性结论沉淀进 `卓望.md` →「历史活动参考」，不要留在会话里。

#### 0b. 往既有省份页里「插一个模块」时的最短路径（2026-09-22 广东 NBA 门票抽奖实测）

不要整页重画。四步：

1. **curl 扒组件树定位插入点**（同上），找到目标区段的分组名与其内部组件顺序，确认「插在哪两个组件之间」
2. **用内置浏览器按 375 宽打开线上页截图**，只看目标区段和上下相邻区段的视觉语言（底色、卡片、标题样式、按钮色），不用看全页
3. **HTML 效果图只画目标区段的上下文**：区段标题 + 上方 1—2 个现有模块 + 新模块 + 下方 1—2 个现有模块，
   新模块加虚线框和「新增」角标；精度未定时按「两版并排」（低保真 / 高保真沿用线上配色）让用户一次选
4. 用户选版后进 Figma，**只画被选中的那版**；主长图同样只画目标区段上下文（375 宽、几百像素高），弹窗一列、说明卡一列放右侧

客户邮件里的「主标题／副标题／按钮」三行是**版块设计**，逐字照抄；配置参数（能量、次数、概率、设备限制）进说明卡不进页面。
邮件与后续截图口径不一致时（如「观众日」vs「球迷日」），以用户最后给的那张为准，差异列入待确认。

### 1. 确认精度（硬前置）

低保真和高保真是两套做法，做错等于返工：

| | 低保真 | 高保真 |
|---|---|---|
| 用途 | 确认结构、模块顺序、状态、跳转 | 视觉方向、领导汇报、对外物料 |
| 视觉 | 黑白灰为主，蓝色只表示可点击 | 完整配色、渐变、实拍素材、精细排版 |
| 素材 | 奖品与素材保留占位 | 可用正式素材 |

两种精度通用：文字优先 Noto Sans SC；可替换字段和素材槽必须有明确图层命名。

用户未说明精度 → 问，不要默认。

### 2. 搭页面结构

模块顺序、首屏内容、CTA 规则、卡片与配色原则全部按
`卓望.md` →「页面设计与原型规范」执行，不要凭印象自拟。

### 3. 覆盖状态

原型必须画出状态，不能只画理想态。状态清单见 `卓望.md` →「页面设计与原型规范」中：

- 任务中心状态、抽奖／轻互动状态、竞猜状态、限时日历状态
- 库存不足、次数用尽、未开放、已结束等边界态

轻互动小游戏的实现结构（点击 → 前端短动效 → 后台校验结算 → 前端展示）同样取自该章；
对用户展示的文案只讲点击动作与可能结果，**不出现「后台同步开奖」等实现术语**。

### 4. 选交付路径

按 `卓望.md` →「交付选择原则」判断，常见三条：

- **快速确认风格** → 直接写 HTML 长页（可点击）+ 渲染 PNG 效果图
- **设计师协作／精确标注／要 .fig** → 画进 Figma（需桌面端 + 插件桥在线）
- **复杂交互／多状态／开发对接** → Figma 高保真互动原型 + 功能标注

功能标注的做法（贴边说明卡、直角折线、图层保留可编辑、FigJam 白板方案）见
`卓望.md` →「全国月度促活与配置化竞猜组件」相关条目。

### 5. 版权检查

无官方素材授权时，不使用官方会徽、吉祥物、奖牌图形、运动员肖像、转播截图和受限口号。
只用泛化氛围元素。

### 6. Figma 出稿默认「②半自动可编辑」（保留自动布局）

三档定义、转换规则与页名约定见 `卓望.md` →「页面设计与原型规范」→「Figma 原型的三档可编辑状态」。
执行口径：**默认出 ②；用户文字指令后才转 ③全可编辑，转前先复制一页存档；定稿交付时可转 ① 锁住。** 不得未经指令提前拆自动布局。

## Design 画布前置（2026-09-19 新增 · 尚未实操验证）

> ⚠ **本节是 2026-09-19 与用户讨论后定下的流程，还没有在真实项目里跑过一遍。**
> 首次实操后按实际情况修订本节；若与上面「步骤 4 选交付路径」冲突，以本节为准，并在修订时同步改写步骤 4。

### 为什么加这一步

用户的实际交付物是**低保真原型 + 文本说明框**，设计师只看图出设计，最终只要 JPG／PNG。
以前的做法是直接在 Figma 里做结构探索——慢、容易误伤、比选要复制整页。
十月促活实测：从页 3 演进到页 9 共七轮，中间还出过一次 Codex 误改 B 版树景的事故。

把**结构探索**挪到 Claude 的 Design 无限画布上做（网页渲染的画板，用户可直接在上面手改），
进 Figma 时结构已定，一次成型。

### 两步分工（关键：两边不做重复功）

**第一步 · Design 画布解决「是什么」**

- 模块清单与顺序、每个模块的结构、页面文案、多方向比选
- **不抠像素、不做精细对齐**——进了 Figma 还要调，在这里抠是白抠
- 用户自己能改的：双击改文字、属性面板改颜色／间距／字号／圆角、把元素拖出容器、包成新的排列容器
- 用户改不动、需要喊助手的：整块重排、批量补弹窗、跨模块的结构调整
- **转 Figma 的时机由用户明确说「结构和文案定了」，助手不要自行判断**

**第二步 · Figma 解决「长什么样」**

- 精确间距与对齐、用户的手改、说明卡与肘形连线、导出 JPG／PNG 交设计师
- 仍按本文件既有的全部规则执行（精度档位、三档可编辑、归档命名、踩坑清单）

### 三条规矩

1. **模块化，不要一整块 4000px 的画板。**
   每个板块一个子文件（头图／快捷导航／活动1／活动2／…），主长图把它们串起来。
   理由：能单独看某一块；改活动3 不会碰到活动4；转 Figma 时一个板块对应一个 Frame，对得上。
   十月「改瓜分板块误伤 B 版树景」的根子就是模块之间没有边界。

2. **转了 Figma 之后，Design 画布冻结。**
   不做双向同步——两边都能改就一定会分叉，然后要人工比对。
   定死：**Figma 是唯一真相，Design 画布留作历史存档。**

3. **低保真阶段不要画插画。**
   SVG 插画转进 Figma 只能变成一张图片或几百条不可编辑的路径。
   低保真的矩形／文字／线／圆角卡片才是 1:1 可转的可编辑图层。
   字体用系统字（苹方／思源黑）——Design 里用 Google 中文字体，到 Figma 没有同名字体会被替换、位置全跑。
   要精美主视觉时才用插画，且那是给领导看方向的比选稿，不进 Figma。

### 什么时候可以跳过 Figma

设计师只看图出设计、最终只要 JPG／PNG，所以时间紧时 Design 画布可以直接导出整张长图和说明卡应急。
**但默认仍然走 Figma**——用户要在自己熟的工具里手改，这是流程的一部分，不是可省的环节。

### 首次实操后要回填本节的

- [ ] 在 Design 画布上画一张完整长图（含弹窗）实际花多久
- [ ] 转 Figma 那一趟，比现在的做法少走了几轮
- [ ] 模块化子文件的粒度多细合适（按板块拆？还是板块内再拆？）
- [ ] 弹窗用模板子组件复用的实际效果（十月那批 29＋4＋3 张是最好的试金石）
- [ ] 用户在画布上手改的实际边界：哪些能自己改、哪些还是得喊助手

## Figma 制作踩坑

- **`resize()` 会重置 auto-layout 的 sizing mode。** 对已设 `primaryAxisSizingMode='AUTO'` 的自动布局帧调用 `resize(w, 10)`，
  高度会被钉死在 10px，内容整块塌陷且不报错。正确顺序是**先 `resize()` 再设 sizing mode**；
  只想定宽时，设完 `resize()` 后补回 `primaryAxisSizingMode='AUTO'`（纵向布局）或 `counterAxisSizingMode='AUTO'`（横向布局）。
  换行容器（`layoutWrap='WRAP'`）同样中招，行高要设成 `counterAxisSizingMode='AUTO'`。
- **按钮文字要靠自动布局居中，不能靠 `x=0` + `textAlignHorizontal='CENTER'`。** 2026-09-07 实测：把文案建成固定 100px 宽、
  `x=0` 钉在按钮左上角，按钮随后被父级自动布局拉伸到 244px，文案不跟随，整块偏左 72px —— 34 个按钮错了 31 个，且
  「设了 CENTER」与「看起来居中」是两回事，只查属性查不出来。正确做法：按钮本身用 `figma.createAutoLayout('HORIZONTAL')`，
  设 `primaryAxisAlignItems='CENTER'` + `counterAxisAlignItems='CENTER'`，文案 HUG，居中就是结构性的，怎么拉伸都不散。
  自查方法：遍历按钮文案，比较 `(t.x + t.width/2)` 与 `(btn.width/2)`，偏差超过 1px 即为错位。
- **文本节点上 `resize()` 会把 `textAutoResize` 打回 `NONE`，文字被钉死在传入的高度里、超出部分静默裁掉。** 2026-09-07 实测：
  写成 `t.textAutoResize='HEIGHT'; t.resize(w,10);` 的换行文本全部只剩 10px 高，截图上看就是「说明文字只显示一行半」。
  正确顺序是**先 `resize(w,10)` 再设 `textAutoResize='HEIGHT'`**；文本放进自动布局后再补
  `layoutSizingHorizontal='FILL'` + `layoutSizingVertical='HUG'`，跟着卡片宽度走，比钉死宽度稳。
  这与「`resize()` 重置 auto-layout sizing mode」是同一类坑，检查时统一看「高度是不是等于我传进去的那个数」。
- **`appendChild()` 没有返回值**，`parent.appendChild(makeNode()).layoutSizingHorizontal='FILL'` 必然抛
  `cannot set property of null`。要么先存变量再设属性，要么自己包一个 `Add(parent,node,fill)` 辅助函数。
- **`figma.createAutoLayout()` 建的帧默认两轴都 HUG，一旦调 `resize(w,10)` 两轴都变 FIXED**，
  于是整列卡片高度全塌成 10px。只想定宽时，`resize()` 后补 `layoutSizingVertical='HUG'`。
- **`node.query()` 的选择器不支持中文属性值**，`FRAME[name^=锚点_]` 会报 `Invalid selector: unexpected character`。
  中文图层名一律改用 `findAll(n => n.name.indexOf('锚点_') === 0)`。
- **解除自动布局（转③全可编辑）时，`layoutWrap='WRAP'` 的容器会先被拍平成一行再解除。** 2026-09-16 实测：29 张弹窗的换行容器
  设 `layoutMode='NONE'` 后全部排到同一行、宽度拉到 9540px，且容器高度只剩第一行、其余被裁掉。转③后必须**重排网格**
  （按列数与间距重算每个子节点的 x/y，再 `resize` 容器到子节点包围盒），并对整页跑一遍「子节点超出父帧边界 → 父帧扩到包围盒」的检查。
  非换行的自动布局帧解除后子节点位置不变，不用管。
- 脚本是**原子的**：报错时整段不执行、文件不变，可以放心改完重跑，不必担心留下半截节点。
- 每建完 2—3 个模块就 `node.screenshot()` 自查一次，塌陷和文字裁切用截图比用返回值更快发现。
- **`page.clone()` 只克隆已加载的内容——源页不是当前页时会克隆出一个几乎空的页。** 2026-09-16 实测：直接 clone 一个未加载的页，
  新页里只有 1 个节点。正确顺序是**先 `await figma.setCurrentPageAsync(src)` 再 `src.clone()`**。另外 **API 不允许删除页面**
  （`page.remove()` 报 Removing this node is not allowed），克隆错了只能改名成「99 空页_请手动删除」让用户手删。
- **在③全可编辑页上改一个模块的高度＝要手动重排它下面所有东西。** 没有自动布局，压缩或撑高某一行后必须：
  ①移动该卡片内后续子节点 → ②resize 卡片与板块 → ③把「内容区」里 y 大于该板块的所有板块整体平移 → ④resize 内容区与主长图
  → ⑤更新「标题_主长图」里的高度数字。漏掉任何一步都会出现模块重叠或主图底部留白。文字改动导致高度变化（多一行小字）同样要走这五步。
- **多个工具在同一个 Figma 文件上干活，接手前先看对方的会话日志。** 2026-09-18 实测：Codex 被派去拉长两个瓜分板块，定位错成 B 版树景、
  拉到 580 后会话中断没还原，用户只说「Codex 改了点东西，你改回来」。正确做法：`grep` `~/.codex/sessions/<日期>/rollout-*.jsonl` 里的 `use_figma` 调用，
  拿到它改过的节点 ID 与新值，再**按主图同场景的原始几何逐项还原**（不要凭印象"大概改回去"）。它自己加的装饰节点按名字前缀（`装饰_`）清理。
- **`use_figma` 返回大段中文会触发 MCP 的 SSE 解析失败（`EOF while parsing a string`）。** 2026-09-18 实测：返回一个 420 字的标注正文就炸。
  只读大文本时用 `encodeURIComponent(text)` 返回再本地解码，或只返回长度＋前 40 字；结构性读取一律去掉 `chars` 字段、分两次拉。
- **接手用户手改过的页面，先整页读一遍再动手。** 用 `absoluteTransform` 取模块绝对位置，把页面顶层节点全部列出来避开已占位置；
  用户可能已改名、删节点、挪位置（如把「活动N」标签删了、把主视觉槽缩小了），凭上一次的记忆写脚本必然找不到节点或盖掉用户改动。
