# 活动策划

> 输入：省份 + 主题 + 核心福利（往往只有一句话）。
> 输出：可交付的策划案。
> 前置：先跑 [开工检查.md](开工检查.md)。

## 步骤

### 1. 补全输入

确认这五项，缺哪项就问：省份、活动主题、核心福利、目标动作、是否含赛事／节日热点。

### 2. 对齐业务目标

按 `卓望.md` →「业务目标与偏好」拆解本次要优先服务哪个目标，不要五个目标平均用力。

### 3. 定主链路

默认闭环见 `卓望.md` →「页面设计与原型规范」中的「常见信息路径」。
无特殊要求时按该闭环组织，有赛事／节日热点时参考「历史活动参考」中最接近的样本。

### 4. 设计奖励体系

按 `卓望.md` →「湖北与内蒙古样本的新增方法论」的**三层组合**与**用户分群优先于福利堆叠**原则配置。
分群维度取自该节，不要自造。

### 5. 做本地化

- 地域线索查 `卓望.md` →「省份本地化策划要求」下对应省份小节
- Slogan 按该章「本地化 Slogan 默认生成方法」执行，默认出 3—5 个方向
- 该省没有现成线索时，参考「省级样本总结」里的本地化强度分级，选一个能落地的档位
- **严禁跨省搬用地域表达**（如把「荆楚」「蒙宠」套到河南）

### 6. 列待确认清单

奖品、数值、库存、概率、兑换门槛、发放方式、活动时间、名单一律进清单，不写成既定事实。
活动时间未确认延期前，对外只表达「暂定至 X 月 X 日」。

## 输出结构

活动背景与目标 → 玩法链路 → 页面模块 → 文案（主副 Slogan／栏目名／首屏）→ 奖励与发放规则 → 状态说明 → 待确认清单

正式 Word 交付时接 [Word交付.md](Word交付.md)。

## 验收清单

- [ ] 五项输入齐全
- [ ] 主链路成闭环，不是模块罗列
- [ ] 奖励覆盖确定性／进度型／随机三层
- [ ] 已按用户分群配置入口与奖励
- [ ] Slogan 给了 3—5 个方向，含一个不依赖谐音的稳妥版
- [ ] 地域元素只抓一个主锚点，无跨省搬用
- [ ] 待确认清单已列出，未把建议数值写成确定口径
