# Word 交付

> 适用：营销活动客服文档、活动策划案，以及其他需要正式交付或导出 PDF 的 Word。
> 检查对象是**整份文档**，不只是表格。
> 前置：先跑 [开工检查.md](开工检查.md)。

## 步骤

### 1. 定版式

默认版式与用「参考 6 月客服文档」时的还原要求，见 `卓望.md` →「Word 客服文档制作与分页规范」。
该章同时规定了字体、字号、章节标题、重点标记与不得使用的装饰元素。

新建 Word／PDF 默认不加页眉页脚；更新既有客服文档时保留原文档已确认的页眉页脚、固定链接与版式。

### 2. 生成时避开的坑（硬约束）

这几条是历次实际踩过的，生成阶段就要避免，不要指望事后修：

- 标题用普通段落或标题样式，**不加项目符号、不绑自动列表**；编号直接写进标题文本
- **不加「与下段同页」（keepNext）、不加 keepLines、不加「段前分页」**（确需新章另起页时才用）
- 表格标题行默认只显示一次，不启用「跨页重复标题行」
- 表格同一行关闭「允许跨页断行」
- 表格标题行不得单独留在页尾，但也不要把整张长表绑成不可分页造成前页大留白
- 「段中不分页」只用于短标题／短提示／小段，长段落允许自然换页

### 3. 内容边界

分页优化**只调整段落、表格、换页属性**，不擅自改业务文字、奖品数据、规则口径、视觉样式和既有信息层级。

从旧稿复制样式时，同时检查段落级和文字级高亮，普通新规则正文不得继承旧修订底色。

### 3.4 月度客服文档「换月只改这些」清单（2026-09-22 首次沉淀，属初版约定，按后续每月生成结果迭代）

全国月度促活的客服文档结构固定，换月时对照上月文档 + 本月原型 + 奖品表，只动下面这些：

| 每月必改 | 来源 |
|---|---|
| 封面与「一、活动名称」的活动名／Slogan | 原型头图 |
| 「二、宣传内容」里的奖品亮点句 | 本月奖品表挑 3—4 个最抓人的 |
| 活动时间、活动链接 | 业务方（未确认前黄色高亮） |
| 「三、活动内容」各【活动N】标题 | **＝原型里各板块横幅名**，顺序照原型；页面有的板块文档必须有（上月文档漏的要补） |
| 各活动的奖品名与「奖品配置」蓝字行 | 奖品表（份数逐项对） |
| 50G 方案编号、北京／辽宁等排除口径 | 业务方 |
| 「四」里两条短信模板中的活动名、奖品名 | 跟活动名与奖品表 |
| FAQ 里的活动名、任务清单、实物奖品清单；新玩法加 1—2 问 | 原型 |
| 业务联系人 | 业务方 |

固定不动（除非业务方明说）：宣传渠道两条、50G 条款与定向流量使用范围、通看券条款（1）—（3）、卡券条款（1）—（9）、
「五、活动规则」五条、「七、投诉处理」口径。
「以承载页面为准」的跳转类板块（周三充值日、观影礼遇等）只写一句并高亮，不展开。

### 3.6 掌厅活动规则：与客服文档并列的另一类 Word（2026-09-23 首次沉淀，属初版约定）

月度促活每月要出**两份** Word，别把掌厅规则当成客服文档的删节版：

| | 客服文档 | 掌厅活动规则 |
|---|---|---|
| 读者 | 客服坐席 | 用户（页面「活动规则」浮层） |
| 篇幅 | 约 9 页，七章 + FAQ | **1 页，六章，无 FAQ** |
| 字体 | 仿宋_GB2312 16 磅（三号） | **微软雅黑 9 磅**，全文一个字号 |
| 覆盖范围 | 咪咕主活动页全部板块 | **只写掌厅这一页的抽奖**；主活动页用一句话带过 |
| 版心 | A4，左右 3.175cm、上下 2.54cm | 同左 |

**六章骨架（照 8 月掌厅规则）：** 一、活动时间 → 二、活动对象 → 三、活动内容（一整段：每日领 1 次机会 + 本页奖品 +
「用户还可以进入咪咕视频客户端参与【本月活动名】限定活动，包括……」）→ 四、本次活动奖品设置（一行奖品与份数 +「实物奖品颜色随机发放」）
→ 五、奖品发放规则（按奖品类型分小节）→ 六、活动规则（5 条，与客服文档「五、活动规则」同源，只改第 2 条列举的奖品类型）。

**做这份文档要注意：**

- **原件的「五、」「1、」是 Word 自动编号（numPr）**，复刻时必须写成死文本，否则违反本文件第 2 节硬约束，且序号会在别人编辑时跳号。
- **「五、奖品发放规则」按奖品类型分小节。** 8 月只有「1、实物奖品」；奖池里出现券类／权益类（如咪咕电影积点券）时必须另起一小节，
  实物那节的条款（填收货信息、20 个工作日寄出）盖不住券类。
- **两页的抽奖机会口径不一样**（掌厅每日 1 次当日有效不累计 vs 主活动页任务获取当月有效），三章里不要混着写。
- 待业务方确认的项照客服文档惯例打**黄色高亮**（活动时间、奖品份数、券类条款）。

### 3.5 分页踩坑（2026-09-20 四川客服文档实测）

- **微软雅黑 12 磅的字面高度明显大于宋体／仿宋**，同样「单倍行距」视觉上接近 1.5 倍，一页只能放约 22 行，分页比预想更容易出孤行。用它做模板时提前按 22 行/页估算。
- **FAQ 答案跨页时，用「在 Q 前分页」把问答整组顺延**，不用 keepNext。实测 Q6 答案末句被拆到下一页顶部成残行，给 Q6 加 `page_break_before` 后整组落到下页，前页留 5 行空白可接受。
- **章节标题落在页尾成孤行时，同样用「段前分页」另起一页**，这是「确需新章另起页」的情形。加了之后要重跑渲染看下游有没有连锁——一页多出一行会把后面每页的末行往下推。
- **Word AppleScript 导 PDF 前先 `open -a "Microsoft Word"` 并等 5—8 秒**，Word 未启动时 AppleEvent 会直接超时（-1712）。
- **用户在 Word 里手改过的 docx，分页属性可能已被编辑动作抹掉**（2026-09-20 四川客服文档实测：Q6 的段前分页在用户改完后不见了，答案又跨页成残行）。
  收到手改版后**必须重新渲染逐页检查**，不能默认上一版的分页还在。
- **段前分页一次只加一处，渲染一次再决定下一处；优先加在章标题上。** 2026-09-22 实测：先给小标题「1、流量奖品」加分页 → 章标题「四、」自己落到页尾成孤行
  → 改加在「四、」上 → 下游「4、积点券」被推成两行残页 → 再撤掉，三轮才收敛。分页会把下游每个标题往后推，一次改两处必然互相打架。
  另：章标题后面跟着首段正文（哪怕只有一行）就算同页，不必强求整章不跨页。
- **python-docx 读旧客服文档时 `font.highlight_color` 会抛 `no XML mapping for 'none'`**——旧文档里有 `w:highlight w:val="none"` 的 run，高层枚举不认。
  读参考文档的字体／字号／高亮／颜色一律直接走 `run._element.rPr` 的 XML（rFonts／sz／highlight／color），不用高层属性。
- **在用户手改版上做局部修改时，只换文本、不重建段落**：取首个 run 的 rPr 复制后清空 runs、新建一个 run 再把 rPr 塞回去，
  字体／字号／加粗／高亮全部保留。用 `paragraph.text = …` 会把 run 格式全部打掉。
### 4. 逐页渲染验收（不可跳过）

把最终 Word 渲染为 PDF 或逐页图片，**每一页都看**，检查：

重复表头 · 跨页断行 · 标题孤行 · 小段独页 · 异常空白 · FAQ 被拆开 · 末页残行 · 中文字体显示 · 表格完整性

奖品规则、黄色提示框、联系方式、投诉处理、文末客服提示等小模块不得只剩一两行单独占页；
文末表格重点检查最后一行是否被拆到独立末页。

### 5. 交付

保留原文件，另存排版修正版／更新版；完成后比对正文文本，确认分页调整未改变业务内容。
交付物应配可复现的生成脚本。
**默认只交 .docx。** 第 4 步渲染出的 PDF 是核验用的中间产物，留在临时目录；用户没主动要 PDF 就不放进交付目录、不发文件卡片（用户 2026-09-22 明确）。

## 验收清单

- [ ] 无自动列表编号、无项目符号绑定
- [ ] 无 keepNext／keepLines／pageBreakBefore（除确需另起页处）
- [ ] 表格未启用跨页重复标题行，未允许跨页断行
- [ ] 已逐页渲染检查，孤行／独页／残行／断行全部处理
- [ ] 中文字体在本地预览下显示正常
- [ ] 业务文字与原稿一致，未被排版动作改动
- [ ] 原文件保留，输出为新版本
- [ ] 固定链接（活动主链接、短链）已核对
- [ ] 掌厅规则：六章齐全、自动编号已写死、券类奖品单起一小节、单页排得下
- [ ] 交付目录里只有 .docx（和脚本），没有顺手放进去的 PDF
