# 交付前检查

> 交付**任何**成品前无条件先跑：策划案、原型、Word、规则、题库、拨测报告都算。
> 本文件只写检查动作；判断口径引用 `卓望.md` 对应章节，不复述。

## 七项检查

| 项 | 检查什么 |
|---|---|
| 数字 | 奖品数量、库存、能量值、概率、次数、门槛、金额——逐个回溯到来源，来源不明的一律标「待确认」 |
| 术语 | 页面用「能量」就全篇用「能量」；首次可写「能量（兑换值）」，之后统一 |
| 状态 | 理想态之外的边界态是否都覆盖：库存不足、次数用尽、未开放、已结束、未登录 |
| 资格 | 参与资格、地域限制、会员等级、新老用户判定是否与规则口径一致 |
| 链接 | 活动主链接、短链、跳转、收货地址逐条点开验证，不靠记忆 |
| 版式 | Word／PDF 按 [Word交付.md](Word交付.md) 逐页渲染检查；原型按精度要求核对 |
| **跨文件口径** | 策划案、原型、Word、活动规则四份之间，同一个数字和同一条规则的表述必须一致 |

**跨文件口径是最容易漏的一项。** 同一批交付里改了任何一处数值或规则，
其余几份必须同步改，不能只改被指出的那一份。

## 事实边界（交付前复核）

- 不编造奖品、库存、概率、方案编码、发放时效、资格或跨 App 适用范围
- **不把原型里的建议值写成正式规则**——建议值必须带「建议」「暂定」「待确认」标识
- **不把公开页面访问成功写成登录态业务流程验证通过**，判定口径见 `卓望.md` →「省级福利中心页面拨测分层」
- 不混用不同省份的规则、福利额度、链接或地方表达
- 活动时间未确认延期前，对外只表达「暂定至 X 月 X 日」

## 验收清单

- [ ] 七项逐项过完，不是抽查
- [ ] 跨文件口径已比对，同批交付内数字与规则一致
- [ ] 所有未确认内容都带显式标识，没有被写成既定事实
- [ ] 建议值与正式规则可区分
- [ ] 拨测类交付已区分「已验证」与「未验证（需登录态）」
